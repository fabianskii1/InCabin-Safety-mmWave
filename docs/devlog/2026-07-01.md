## 📊 결과 · 데이터
- 캡처 파라미터: 10FPS, 256 samples, 128 loops, 3TX/4RX.
- stop.bin(부동자세 호흡) 600프레임, threshold=4.123 기준:
  - score min=3.826 / mean=4.047 / max=4.734 / std=0.191
  - 순간 판정은 호흡 주기에 맞춰 PRESENT↔empty 깜빡임. 중간에 최대 ~4초(43프레임) empty 구간 존재.
- empty 바닥 ≈ 3.85~3.95 / 사람 피크 ≈ 4.2~4.7 → 순간값은 일부 겹침(사람 저점이 empty와 겹침).

## 🐞 문제 & 해결
| 문제 | 원인 | 해결 |
|------|------|------|
| point cloud가 프레임당 128개 고정 → 유무 판정 불가 | `EnergyTop128`(상위128 무조건 선택) + `reg_data`(128 강제 패딩). 신경망 입력용이지 탐지용 아님 | 점 개수 대신 clutter removal 후 Range-Doppler 에너지(정지성분 제외 최대)를 score로 사용 |
| `capture.py`가 "Packet Lost" 후 멈춤 | `steaming.py`가 패킷 1개만 손실돼도 `exit(0)`로 수신 스레드 종료 → 메인은 무한 대기 | 재시도 / PacketDelay 25→50 상향 (근본책은 손실 시 프레임만 버리게 수정 필요) |
| 정지 호흡 시 판정이 프레임마다 깜빡임 | 호흡=주기 운동이라 흉부 '움직이는 순간'에만 에너지 튐. clutter removal이 완전 정지는 제거 | 슬라이딩 윈도우(`--window`) + 초과비율 임계(`--present-ratio`)로 시간통합 |

## 🤔 결정 사항 (왜)
- **유무 판정은 점 개수가 아니라 에너지로 한다** — 템플릿 point cloud는 항상 128개라 개수 정보가 없음.
- **판정은 프레임 단위가 아니라 시간(윈도우) 단위** — CPD(잠든 아기)엔 안정적 유지가 필수. 순간 깜빡임은 오판 위험.
- **극도로 정지한 대상은 에너지 방식의 한계** — 4초 empty 구간이 그 증거. 근본 해법은 **위상(phase) 기반 호흡 감지**(다음 마일스톤, RR 추출과 동일 경로)로 가기로.
- 홈 디렉토리에 잘못 만들어진 git 저장소(`~/.git`, 9GB) 정리 — 졸과 폴더 중첩 해소.
